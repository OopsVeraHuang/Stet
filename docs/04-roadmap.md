# 交给新窗口的实施顺序

每次只交付一个能点击理解的纵向切片：解释目标 → 本地实现 → 测试 → 给出操作和结果 → 记录局限。阶段没有虚构工期或完成日期。

| 阶段 | 用户能看到的东西 | 验收 |
|---|---|---|
| P0 当前 | 本交接仓库、架构、虚构数据、参考模块 | 离线 smoke tests，隐私扫描，本地 Git |
| P1-A | 导入向导、记忆列表、原文弹层、查询框 | 无 API 即可验证规范 JSON/MD 的导入和词句检索；错误角色/时间可见 |
| P1-B | 真正的本地混合 RAG、修正/撤回和上下文预览 | 另行下载核验模型；中英俄独立题集；修正持续有效，删除无残留 |
| P1-C | 两种模型切换、工具事件、逐消息费用 | 填测试 API 后少量可控实测；提供失败恢复，不使用私人账户 |
| P1-D | 文献片段共读、浅色学习模式、可回源笔记 | 用原创或可再分发示例验证笔记与聊天共用索引 |
| P2 | 更多导入适配器、可控视频观察、手机适配 | 浏览器与真实设备验收；不能只用桌面模拟器 |
| P3 | 发布候选、安装指南、许可证与贡献流程 | 干净环境安装、数据隔离、备份恢复、依赖归属、Git 历史扫描 |

第一阶段不做 App Store 原生客户端、语音克隆、无人监管的自我改代码、多租户 SaaS 或持续主动消息。这些可以独立扩展，不阻挡记忆核心展示。

## 第一次打开新窗口时做什么

先阅读本仓库，确认“已实现”和“待接入”；运行离线测试；提出 P1-A 的三屏草图（导入、记忆、聊天/上下文预览），随后直接在独立目录实现。不要从私人项目整目录复制。默认无 API、无联网请求，用虚构记录完成可操作链路。

## 用户如何学会理解

先解释五个词：前端是看到的页面；后端是处理消息的程序；数据库是保存记录的地方；API 是请求外部模型的接口；Git 是可回退的代码版本记录。暂时不用同时学完编辑器、部署和模型训练。

每个阶段只要求用户体验、说明预期、比较两种设计；编码助手负责依赖检查与命令执行并留下步骤。逐步让用户能画出一条消息的数据流、解释关键取舍和评价结果。不要把原型建设变成无限工程债；达到展示核心即可停下做研究分析。
