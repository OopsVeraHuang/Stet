# 怎么证明原型有用，而不是功能多

## 第一阶段：虚构数据、零付费检查

检查完整导入、说话人、分支隔离、重复导入、时间未知、原文引用、修正/撤回、删除后索引移除和短窗口承接。覆盖中英俄。仓库中只附少量虚构 smoke cases；它们不是完整 benchmark，不证明跨语言检索质量。

预先编写 gold evidence：问题应由哪些原文支持；哪些不能回答；冲突应如何呈现。不要边修改检索规则边把同一组开发题的分数当泛化性能。独立保留一组未用于调参的测试。

### 时间与纠正联动的待实现验收

`examples/governance-cases.json` 是完全虚构的**描述性验收规格**，顶层状态为 `planned_not_executable`。它没有接入运行时，也不由现有 8 项参考模块测试执行；JSON 能被解析不代表这些行为已经通过。P1-B 实现后，将这些案例转成上下文组装与状态变更测试，再增加独立保留题。

| 案例 | 要核对的结果 |
|---|---|
| T01–T04 | 同一天相隔数小时；延迟导入不改变事件时间；“昨天”以原消息时间为参照；未知时间或时区保持未知 |
| C01–C03 | 召回旧消息连带其有效纠正；替代关联指向旧纠正；撤回后重算状态，不悄悄复活被替代版本 |
| C04 | 没有明确替代关系的冲突保留为待澄清，不按最后写入自动判真 |
| B01–B02 | 旧证据与有效纠正一起进入上下文；预算不足则去掉旧证据，不能留下未经纠正的旧版本 |
| S01–S04 | 明确长期要求成为全局偏好；普通事件纠正只随话题召回；引文和假设不升级为全局偏好 |

区分两层验收：第一层检查存储和组装出的实际上下文，第二层才检查 LLM 的回答是否遵循。前者通过不能推出后者始终服从。为每次组装记录候选消息 ID、关联纠正 ID、有效/撤回/冲突状态、保留或舍弃原因和输入预算；日志使用合成内容，正式部署另行执行隐私与保留策略。

这组测试同时连接 RQ1 与 RQ3：测量纠正是否随证据进入上下文，以及付出的额外输入量、因此舍弃的证据量。单独报告“被召回的已关联旧证据缺失有效纠正”的次数；没有建立关联的漏召回也需记录，不能从分母里隐去。缓存命中、命中 token 数与费用来自供应商用量，未运行付费实验时记为“未测”，不从稳定前缀推定节省比例。

## 第二阶段：在同一任务上比较配置

候选条件：A 只有短上下文；B 词句 RAG；C 混合 RAG；D 混合 RAG 加可见出处与可撤回修正。固定模型版本、温度、任务、输入预算等条件；分别测试模型 A→B 切换前后。环境差异必须报告，不能把更大的输入预算叫算法胜利。

外部基线需要记录具体版本和配置：Mem0 至少区分默认 `infer=True` 的抽取式记忆与 `infer=False` 的原始消息保存；Letta 记录核心记忆块是否可编辑、归档内容、历史检索工具和上下文预算。不把产品名称当成单一算法，不把可配置的能力描述为产品必然缺陷。各配置使用同一批有授权的合成源消息，并分别报告存储内容、自动推断、更新/纠正方式、检索预算及模型调用费用；运行和适配成本也需披露。

“有损压缩、语用信息变平、错误推断持续影响回答”是待检验的失败类型。评价需同时检查原件是否仍可追溯、机器解释是否被误当成用户确认的事实、纠正是否传播到后续回答。不能仅凭某次回答较短或更讨喜就判定一种记忆范式优越。

检索指标：evidence recall@k、错误说话人/分支率、日期命中、未知问题误召回。回答指标：无依据的记忆断言、引用是否支持陈述、修正采纳与撤回恢复、当前对话承接。体验指标：用户能否理解为什么记起这件事、能否修好一次错误、主观连续性与控制感。效率：每用户消息所有请求的实际输入/输出/缓存用量、待核对费用、端到端时间。

连续性评价不能只数相同词语。设计匹配场景，观察解释深度、称呼边界、幽默方式、独立判断、用户改变后的适应。保留“太像旧版本而不愿改变”的失败类型。

## 第三阶段：小规模形成性研究

可考虑 4–6 位符合目标的成人进行可用性试用与访谈，作为研究设计建议而非统计功效保证。先确定招募、同意、删除和去识别方案；涉及正式人类参与者研究时按所在机构伦理流程办理。初期无需参与者上传真实亲密记录，可提供虚构情境。

问题例子：切换模型前后哪里像/不像同一个伙伴？你能解释这条回答受哪段记忆影响吗？纠正后你期待哪些变化、哪些不应变化？不以满意度单项代表稳定关系或心理健康效果。

## 作品集演示：3–5 分钟

1. 用虚构人物导入两个来源的十几条记录，展示导入问题预览。
2. 换一种语言提问，真实检索到证据；若未运行语义模型，清楚标记为词句演示。
3. 打开出处和时间线，区分旧安排与当前状态。
4. 用户修正并撤回一项设定，展示下一次上下文实际变化。
5. 切换两个真实可用模型，展示可比较的结果，不预录伪装现场生成。
6. 阅读一段自写示例资料，把有用回答存入笔记并跳回原消息。

演示视频、系统图、1–2 页 case study、可复现仓库和局限列表是第一套产出。只有确实完成的步骤才能出现在“结果”里。

参考：[CHI 2026 研究透明性建议](https://chi2026.acm.org/guide-to-a-successful-submission/)。研究计划与软件测试通过不等于完成用户研究，也不承诺博士录取或资助。
