# 项目定位与研究问题

## 一句话

Stet（let it stand，原工作名 Continuity）是一个让用户能够携带、检查、修正并有选择地使用共同经历的个人 Agent 交互平台，研究在基础模型改变时，交互关系如何保持连续，又能接受用户主动改变。

英文作品集描述草案：A research prototype exploring how user-governed, provenance-preserving memory can support relational continuity across language-model changes.

不要写成“已经解决了人格固定”。跨模型行为稳定是待验证目标，不是存入一段 system prompt 就能保证的事实。

## 面向谁

首批对象：已经长期使用对话式 AI，并跨会话或跨平台保留重要记录、希望延续特定协作方式的成年人。典型场景包括长期学习伙伴、创作搭档、研究助理与陪伴对象。

首轮招募应收窄为“有跨平台/跨会话延续需求的长期用户”，而不是试图代表所有 AI 用户。亲密关系使用者可以是其中一种重要经验，不需要隐去，但不必把所有界面预设为恋人关系。用户自己定义 agent 名称、关系用语、称呼和边界。

## 核心张力

稳定不是每次说同一句话。个性化不是机械甜言蜜语。理想状态是：表达与关系理解有连续性；事实修正和用户改变能真正影响后续；新模型仍保有独立分析与不同意的能力。

可操作化为四个维度：
1. 事实与时间连续性：不把旧场景误说成现在。
2. 交互偏好连续性：称呼、解释深度、幽默方式等不随换模型意外消失。
3. 关系边界连续性：明确纠正和撤回持续有效。
4. 适应性：用户表示改变之后能够更新，不以“保持人格”为由拒绝改变。

## 第一原型回答的问题

- RQ1：可见出处、可撤回修正的记忆界面，如何影响用户理解、控制和修复 Agent 行为的能力？
- RQ2：切换模型后，哪些交互特征能够通过记忆与用户设定延续，哪些仍受基础模型影响？
- RQ3：缩短近期窗口、按需召回的设计，在费用、延迟和关系连续体验之间有什么取舍？

第一版以 RQ1 为主、RQ2 为探索，RQ3 提供工程解释。不要同时把三项都宣称为已完成贡献。

## 候选贡献与已有工作

RAG、向量检索、RRF 和提示词本身都不是本项目发明。候选 HCI 贡献在于：把跨平台记忆迁移、证据可见性、用户修正及跨模型连续性放进同一套可交互、可比较的研究工具中。是否具有新颖性仍需相关工作比较。

Mem0、Letta 等应成为待比较的工程/研究基线，而不是用“我们的记忆更好”替代实验。两者不能统一称为“只有后台摘要”的系统：

| 比较配置 | 机制与需要明确的边界 |
|---|---|
| Mem0 默认 `infer=True` | 模型从消息中抽取事实、偏好等，再管理记忆；需要观察抽取时保留了什么、遗漏了什么。 |
| Mem0 `infer=False` | 支持跳过模型推断、直接保存消息；应作为原文保存配置单独比较，不能声称 Mem0 一律不保留原文。 |
| Letta 分层记忆 | 核心记忆块可由 Agent 管理，也可设为只读；另有原文归档与会话历史检索。比较时须记录记忆块权限、检索工具与实际配置。 |

依据：[Mem0 官方 Add 文档](https://github.com/mem0ai/mem0/blob/main/docs/core-concepts/memory-operations/add.mdx)、[Letta 官方 Memory Blocks 文档](https://docs.letta.com/v1-sdk/memory/memory-blocks)、[Letta 归档文本接口](https://docs.letta.com/api/typescript/resources/agents/subresources/passages)。这些是设计参考；实验时还须固定实现版本与配置。

本项目采用“原件优先 + 用户显式治理”（Archive-First & User-Governed Provenance）：保留可追溯原文，将机器解释与用户确认的信息分层管理，召回旧记录时联动其有效纠正。系统仍会分段、排序、推断和回答；这里的承诺是机器推断不能未经明确规则升级为权威持久事实，而不是“机器只检索、不推断”。

用户掌握个人偏好、关系定义与个人陈述的纠正权（Correction Override）。纠正改变后续解释，不擦除历史原件；涉及外部事实的冲突时保留证据和不确定性，不把用户治理等同于无条件同意。

研究将检验不同配置是否产生有损压缩（Lossy Compression）、语用信息扁平化、错误推断延续，或纠正未能持续影响回答的问题。这些是待验证风险，不是预先断定所有基线的必然缺陷。原件优先也不能消除召回遗漏或模型误读。纠正与原文联动的设计同时连接 RQ1 的可修复性和 RQ3 的长期上下文预算；其运行机制待 P1-B 实现，不能列为已验证贡献。

记忆问答正确率不等于人格连续，也不等于用户允许 Agent 根据推断采取行动。

## 你的角色与作品集

作者可负责问题形成、访谈/场景、交互设计、评估标准、失败案例分析和取舍；编码助手协助实现。应记录 AI 辅助范围和自己作出的设计决定。无需为了展示而假装全部代码由自己手写；但需要能解释主要数据流和为什么这样设计。

私人使用经历是第一人称设计动机与问题来源。未经过方法设计的日志不自动成为正式数据集、用户研究或完成的自我民族志。公开演示用虚构数据，不需要公开私人关系记录。

参考：[ACM CHI 2026 Contributions to CHI](https://chi2026.acm.org/contributions-to-chi/) 明确区分系统、交互技术和理解用户等贡献，强调实现边界与适当验证。这里引用研究评价思路，不是招生规则或录取保证。美国项目的资助条件需要逐校核验，原型不能替代资金核对。
