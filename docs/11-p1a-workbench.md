# P1-A：第一次点击 Continuity

本次只引入一个概念：**出处**就是“这句话从哪个文件、哪条消息来”。看到原话并能返回文件，才能检查系统有没有记错。此处的记忆是档案记录，不代表已确认的事实。

## 怎样打开

Windows 已有 Python 3.11+ 时，双击仓库中的 `启动原型.cmd`。它会打开浏览器；保留启动窗口，结束时关闭窗口。其他系统在仓库目录运行 `python -X utf8 -m continuity --open`；若只有 `python3`，替换命令名即可。没有新增运行依赖，无 API key、模型下载、订阅或付费请求。

若此刻使用的是 Codex 云环境，云端的 127.0.0.1 地址不能在你的电脑访问。在私有 PR 的功能分支页面选择 Code → Download ZIP，解压后双击上述文件。不要直接双击 `index.html`，它需要与本机保存记录的程序一起启动。

## 三屏，三分钟

| 在哪里点 | 看见什么算成功 | 它还不能证明什么 |
|---|---|---|
| 导入 → 预览 JSON 示例 | 6 条消息，缺失分支/时区有提示；此时尚未保存 | 不证明任意平台导出都可导入 |
| 确认导入 → 记忆 | 6 条原话；用户与助手标签分开 | 助手说法不因此变成用户确认的事实 |
| 原文检索 → 输入“松湾” → 查找原文 | 找到 2 条；不会出现生成的回答 | 不能搜到同义词不等于相关经历不存在 |
| 查看出处 | 完整原文、角色、来源、对话、分支、记录时间和本次导入时间；可下载原文件 | 不解析“昨天”的日期，不自动决定纠正是否有效 |
| 导入 → 预览 MD 示例 → 确认导入 | 再新增 4 条，总计 10 条；记忆中选 alternative 分支只看到 1 条 | 不证明手机后台或真实手机行为已验收 |
| 再次预览相同 JSON | 显示已导入，确认按钮不可用，不新增消息 | 不自动把内容相近的不同消息合并 |
| 记忆 → 重建检索索引 | 显示 10 条，搜“松湾”仍是 2 条 | 这里只是字面查找，不是向量或语义召回 |
| 记忆 → 管理已导入的文件 → 撤销整批导入 | 先确认，再报告移除数；全部撤销后列表与索引为 0 | 不删除电脑上原来选中的文件、下载副本或备份，不承诺磁盘取证级擦除 |

出错时先看页面提示：不支持的角色、非法时间、缺少 ID 或同一消息身份的内容冲突会阻止整批导入。修正源文件后重新预览。缺失角色或时间可以保留为未知；不会拿导入时间填空。

## 已采用的实现取舍

| 问题 | 本轮选择 | 可比较的另一方案与代价 |
|---|---|---|
| 一个文件有错误怎么办 | 整批拒绝，逐条显示原因；没有静默跳过 | 部分导入有效行更快，但需更复杂的补导入与失败行治理；留到后续讨论 |
| 原文件留不留 | 原始字节随导入批次保存，可下载；撤销批次一起移除 | 只存提取后的消息更省空间，但无法核验完整源文件；本轮优先可追溯 |
| 如何检索 | Unicode 大小写折叠后的连续字面子串，中文不依赖分词 | 语义模型可找同义内容，但需依赖/模型核验与质量评估；P1-B 再做 |

没有引入关系角色预设、人格自动学习或真实模型结果。研究主线仍是用户治理与可修复性；本轮只提供检查出处的可操作基础。

## 文件与数据契约

- `continuity/importing.py`：UTF-8 规范 JSON/MD 解析及逐条错误/缺失提示。
- `continuity/store.py`：SQLite 原件、消息、出处关联与可重建字面索引。每个数据目录一个独立实例。
- `continuity/server.py`、`continuity/static/`：仅本机三屏服务与界面。来源文本用纯文本显示，不执行其中 HTML/指令。
- `examples/messages.json`、`examples/messages.md`：6 + 4 条完全虚构消息。
- `tests/test_workbench.py`：17 项 P1-A 回归；原 8 项参考模块测试保留。

JSON 顶层为 `{"messages": [...]}`，每条须包含非空字符串 `id`、`source_id`、`conversation_id`、`text`。`role` 可为 `user/assistant/system/tool/unknown` 或缺失/null；其他角色会报错。`recorded_at`/源 `imported_at` 如提供须为 ISO 日期或时间。`branch_id`、`timezone`、`time_precision` 可缺失/null，缺失不补齐；支持的精度是 `day/minute/second/unknown`。不做时区转换或相对事件日期推断，未识别的时区保留并提示。原字段及所有未知扩展字段均保留。

消息身份是 `(source_id, conversation_id, branch_id, id)`；未知分支以缺失身份处理，不假设为 main。相同身份且字段相同的消息可由多个原文件共同引用，各文件位置均保留；相同身份而字段不同则报冲突，不能静默覆盖。一次文件内的重复位置也可追溯。

MD 以 `# Continuity transcript v1` 开头，每条使用 `<!-- continuity-message: {一行 JSON 元数据} -->`，随后直到下一个标记均为原文，包括空白和换行。模板在界面可下载。该标记行是保留语法，不能放入正文表示普通引文；不自动识别普通 Markdown 的标题/颜色角色。JSON 用 `/messages/N` 定位，MD 用元数据与正文行号定位；完整原文件同时保存 SHA-256。

顶层 `corrections`、`observations` 等扩展分开保留在原文件与扩展数据中，不加入消息查找目录；消息的 `event_time_note` 原样展示。`scope=global/topical`、`target_message_ids`、`supersedes` 的语义校验、状态机、关联/成组预算、撤回不复活旧版都仍是 P1-B 契约。保留字段不代表实现机制，14 个治理案例仍为 `planned_not_executable`。

当前每文件上限 2 MiB / 2,000 条，不支持 JSONL、DOCX、平台原生导出、批量扫描目录。列表尚未分页，字面索引采用线性查询；不宣称已测长期大库性能。

## 保存、检查与回退

默认运行目录是仓库 `.local/continuity/`，被 Git 忽略；可用 `--data-dir /独立目录` 改位置。原文件字节保存在该目录的 SQLite 中，预览不持久保存。重启后数据仍在。预览和检索不会发出外部网络请求，服务仅绑定 127.0.0.1，不可直接当多人托管服务。

撤销导入在一个事务中删除该批原文件/扩展与出处关联，并删除没有其他批次引用的消息和对应索引。界面报告剩余数量；重建不会复活已删除消息。取消确认不会删除。SQLite 开启 secure_delete，但没有承诺擦除操作系统缓存、旧备份、下载文件或存储设备历史。

验收命令：

```text
python -X utf8 -m unittest discover -s tests -v
python -X utf8 tools/package.py verify
```

开发者若环境已经有 Playwright 与 Chromium，可加 `node tools/check_browser.cjs`。该脚本自己启动临时实例并清理数据，只把虚构截图放在 `.local/browser-check/`；它不是使用本应用的前提，也不自动安装浏览器。可用 `CONTINUITY_PYTHON` / `CONTINUITY_CHROMIUM` 指定已有程序。

Git 功能分支为 `feat/p1a-memory-workbench`。回到 P0 可切换至 `ea9d380`，不重写历史、不删除用户数据；P1-A 的数据目录会留在原处但 P0 不读取它。合并后的回退应用正常 revert 流程并重新生成包清单。没有改动 `reference_core/` 或私人 companion 项目；没有部署公网、选择整体许可证或发布开源版本。
