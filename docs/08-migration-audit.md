# 通用化审计与新窗口检查表

2026-10-23 的只读代码审计发现，私人先导系统可以提供经验与模块，但不能整体搬成公共模板。

1. 私人部署打包脚本会包含历史库、状态库和书籍原件，不能复用于公开发布。
2. persona、SYSTEM、默认路径、位置种子、界面名称及回归题中含个人配置；新版本全部改成用户配置和虚构数据。
3. 当前入口依赖现有原文档案；新原型必须从空数据库创建 schema，不可依赖私人数据库初始化。
4. 一次性历史整理脚本需要改为可重复、可撤回、可预览的导入任务。资料库文件提取不等于聊天导入。
5. 原先测试读取真实档案；新测试必须使用临时库与虚构来源，不继承读取私人库的测试基类。
6. 全局状态与单个 SQLite 是单用户架构，不足以支持多人托管。
7. 模型目录、价格和能力不能只复制旧表；发布时核对实际可用模型，配置持久化有版本。
8. 供应商订阅桥与普通 BYOK API 是不同接入方式，不共享个人登录文件。
9. 原始更新日志包含私人路径、语料及诊断细节，本包只保留重新编写的工程经验。
10. 原阅读器使用的 PDF.js/Foliate 及其字体/WASM 等有各自许可证；如以后移植对应资源，必须保留相应许可并建立第三方清单。本包没有复制这些资源。

工作室的现有能力是检查、记任务、写修复建议与审计，不是直接运行任意命令或自我部署。原型可以显示“请求帮助/提出修复”，不能把未执行的动作显示为完成。

视频保持实验功能；不把旧的离线音频队列测试当成跨设备实时质量验证。不发布影视角色克隆音色或第三方声音素材。

## 新窗口第一轮验收

- 独立目录、独立 Git、独立 runtime，无生产连接。
- 虚构规范 JSON 成功导入；缺失时间与无效角色可见；重复导入不重复创建记录。
- 检索返回原文并可回源；没有模型也能演示。
- 每个“已完成”有文件/命令/操作证据，错误不悄悄吞掉。
- 用清楚的界面状态区分“词句检索”“语义尚未启用”“供应商未配置”，不伪造在线能力。
